# cube 项目现状

> 本文件是 cube 项目的**事实快照**——描述当前代码「是什么」，基于代码现状反向提取。
> 与 [`../proposals/`](../proposals/) 的关系：本文件是「现状」，proposals 是「未来要做什么」。
> 维护节奏：每次合并一个有意义变更后同步更新。与代码冲突时以代码为准。

---

## 一、定位

**cube** —— 面向个人开发者的本地项目管理工具（**Web UI 优先，CLI 简单可行兜底**）。Go 1.27 编写，module path `cube`。

- 历史有三代：v1 (php)、v2 (go)、**v3 (当前，按领域重构)**。
- 出口：本地 Web HTTP server（`cube server`，huma + 标准 ServeMux，主要交互形态）、CLI（人用 / alfred，web 不可用时兜底可行）。
- 定位原则：不做云服务、不绑 AI（cube 可被 AI 编排，但自身不集成 AI）。

## 二、分层架构

```
基础设施  internal/config / internal/logger / internal/version                 所有层共享
独立工具  pkg(git / gitapi / fuzzy / easycache / pathkit / tui / xstore)  通用动作, 不含业务实体, 只依赖标准库/第三方（文件存储原语在外部包 github.com/heyuuu/x/store；通用 std 扩充在外部包 github.com/heyuuu/x/xstd——xslices / xos 等）
能力      internal/server                                        服务端框架, 不含业务实体
领域      internal/domain: project (含 snapshot / scan / clone / cubefile / workspace) / usage / workbench / forge / opener / template / icons   业务 domain, 含实体和规则
出口      internal/cmd / internal/handlers / web                 把领域包成 CLI/Web；handlers 是业务 HTTP handler 层；web 包只剩前端构建产物 go:embed 容器（embed.go），服务端框架在 internal/server
装配      internal/app / cmd/cube/main                           接线（cmd/devtool 是脚手架工具的独立入口）
```

**依赖纪律**：**pkg 是独立工具层**（只依赖标准库/第三方），基础设施层与能力层都可以依赖 pkg（如 `internal/logger → pkg/tui`）；基础设施不依赖上层；能力层不依赖领域/出口；领域层依赖能力+基础设施+pkg；`handlers` 依赖领域层与 `internal/server` 框架；**cmd 与 web 不互调**（cmd 对 server 进程的探活/关停走 localhost HTTP（helper 在 `internal/cmd/server/helpers.go`），是进程间通信，不算互调）；`internal/app` 是唯一接线点（`app.New()` 建空壳 + `App.Init` 组装，见 3.4）。

**扩展模型**：加一个新 domain = ①`internal/domain/<x>` 领域包 ②`internal/cmd/<x>.go` 子命令（+ root.go 注册） ③`internal/handlers/` 加 `<domain>_handler.go` ④config 加节（如需） ⑤`internal/app/boot.go` 注册清单加构造。五处都是加法，不碰现有 domain；脚手架已工具化——`just gen domain <name>` 自动完成（生成器在 `cmd/devtool/internal/generate`，以 boot.go 注入点标记为锚点追加）。

## 三、关键机制

### 3.1 项目前提：所有项目都是 git 项目

`.git` 存在且为**目录**是扫描判定项目的必要条件（详见 `internal/domain/project/scan.go`）。因此 `tags` 不打冗余的 `git` 标签，只标额外特征（`godot`）。`.git` 为文件的 linked worktree 不是项目（1032 归并）：它是所属主项目的一个**打开目标**——`project = git 仓库身份（主仓库 root）`，打开目标 = { 根目录, 主项目 workspaces…, 各 worktree 根及其 workspaces… }（1030）。规则：主仓库必须在 scan-rule 之下，worktree 可在任何位置，其可见性来自主项目快照的 `worktrees` 枚举（`git.WorktreeList`，采集时附带，读路径只读快照）。worktree 目录被 scan 跳过（同隐藏目录待遇，不再遍历子目录）；主仓库不在任何 scan-rule 下的 worktree 整体不可见（接受）。命中 worktree 目录的场景由 `project.Service.ResolveProject`（`git.FindMainRoot` 向上归并到仓库主工作树根：普通根/子目录即仓库根，linked worktree 顺着 `.git` 文件定位主仓库）归并到主项目——CLI `info` 在 worktree 内执行等同操作主项目根（额外注明当前所属 worktree）；CLI `pull/push` 已脱离 project（见四、命令列表的 `git` 组），worktree 归并直接走 `git.FindMainRoot`；打开目标查询走 `cmdutil.OpenTargets(snap)`（cmd 层工具，CLI 专用出口：`cube open` 交互选择、alfred 平铺展开；Web `project/open` 的归属校验不走它——按「项目领地」校验（`Service.ResolveProject` 归并后比对主项目），放行 OpenTarget 集合之外的子目录；Web 前端也不消费它——无对应 HTTP 端点，前端下拉从 list DTO 快照字段自拼同一套排序，改排序/展示规则时两边同步）。排序定稿：主根 > 主 workspaces > worktree 根 > 其 workspaces；worktree 展示名取分支名、冲突/detached 回退目录名，workspace 取「[worktree 标签 · ]声明/推导名」（worktree 下恒带归属前缀，前缀后仍撞名的 workspace 追加相对路径后缀，worktree 根不追加）；目标带 `Flags` 位标记（`FlagWorktree`/`FlagWorkspace` 可组合——worktree 下的 workspace 目录 = 两者叠加，根目录 = 0），判定用 `IsWorktree()`/`IsWorkspace()`

### 3.2 snapshot 项目快照定时刷新（原 projcache）

项目状态快照（分支/ahead-behind/dirty、worktree 枚举、workspace 成员等）缓存在 `~/.config/cube/cache/snapshot.json`。读命令从缓存读快照（几乎零开销），**读路径不阻塞、不触发采集**。

刷新机制按进程类型区分：

| 进程 | 读 snapshot.json | 触发刷新 |
|---|---|---|
| **server**（常驻） | 启动时 Load 一次 | 进程内 goroutine 按数据新旧定节奏 `Refresh`（保证缓存距今不超过 5 分钟）→ 写内存 + flush snapshot.json |
| **CLI**（短命） | 启动时 Load 一次 | **不刷新**，只读启动时 Load 进来的快照 |

机制要点（`internal/domain/project/service.go` + `internal/domain/project/snapshot/cache.go`，重构记录见 [`docs/proposals/archived/1004-snapshot常驻化重构/`](../proposals/archived/1004-snapshot常驻化重构/)）：
- **server 刷新循环**：刷新 goroutine（私有 `startRefreshTicker`，公开面仅 `OnServerStart`/`OnServerStop` 钩子）节奏由数据新旧决定——每轮取两个时间戳（`scanCache.UpdatedAt` / `snapshotCache.EarlyUpdatedAt()`，由各缓存自记）中更过期者计算下次时机，保证距今不超过 `maxExpireTime`（5 分钟）：冷启动（时间戳零值）立即刷新避免空窗；热重载（两时间戳均新鲜，如 air 重启进程）自然算出整周期等待、不重复全量重采；刷新失败时间戳不推进，按整周期退避重试防热循环。刷新 = `Refresh`（重扫项目列表毫秒级 + 按最新路径列表整表采集 git 数十秒级 + 落盘）；两个新鲜度时间戳经 web list/info 接口返回，前端分别判断。装配点在 `internal/cmd/server/start.go`（`cube server start`：`a.StartBackgroundJobs()` → `Server.Start()` → defer `a.StopBackgroundJobs()`），CLI 装配不调。
- **单写者模型**：server 是 snapshot.json 唯一写方，CLI 只读不写，无跨进程并发写。落盘靠 `Save()` 的原子写（`store.WriteFileAtomic`，tmp + rename，`github.com/heyuuu/x/store`），无需 flock。
- **snapshot.json 角色**：跨重启持久化缓存——server 重启后秒恢复，CLI 读最近一次落盘（server 没跑时快照可能略旧）。
- **降级优先**：刷新 goroutine 内 recover，采集异常不拖垮 server 进程。
- **采集可观测**：每次 `Refresh` 完成写一条汇总日志（项目数/成功/失败/开始/结束/耗时），排查「缓存为何没更新 / 采集耗时异常」直接查 `app.log` 这一条。
- **CLI 触发例外**：`cube dev refresh-snapshot`（Hidden 调试命令）可手动触发同一路径的刷新（重扫 + 采集 + 落盘），供开发期实测采集耗时；业务 CLI 命令仍严格只读。

### 3.2.1 monorepo workspace 规则（`.cube/cube.json`，1030）

monorepo 子目录（如本仓库 `web/`）可作为项目打开目标。声明文件在项目根 `.cube/cube.json`（进 git，跟仓库走；linked worktree 各分支检出各自内容，path 相对各自所属根）：

```json
{ "workspaces": [ {"name":"server","path":"server"}, {"path":"apps/*"}, {"path":"<pnpm>"} ] }
```

- **文件格式层 `internal/domain/project/cubefile`**：cube.json 是「项目自身的 cube 配置」多节容器（当前只有 workspaces 一节，未来项目级声明同归此），节级读写（节缺失哨兵错误 / 未知节保留 / 原子写）走外部包 `github.com/heyuuu/x/store` 的 section API；各节业务语义归各自 domain（workspace 规则解析在 `internal/domain/project/workspace` 包，纯函数）。
- **规则模型（单配置）**：`workspaces` 节是 `WorkspaceRule{name?, path}` 清单——path 为相对根的**精确目录** / **glob 通配**（`apps/*`、`packages/**`，doublestar 展开、排除隐藏与 node_modules）/ **特殊规则** `<npm>`（读 package.json workspaces，数组或 `{packages:[]}` 两种形态）/ `<pnpm>`（读 pnpm-workspace.yaml）——旧的 `workspaceScanRule` 探测规则组合被 `<npm>`/`<pnpm>` 特殊 path 值取代。**节缺失（或文件缺失）走程序默认规则 `<npm>`+`<pnpm>`**；坏 JSON 降级为无规则（无 workspace，不回落默认——避免掩盖手工搞坏的文件）。name 是可选显示名：通配/特殊规则作组前缀（`name:rel`），缺省用相对路径本身。
- **解析**：`workspace.Resolve` 按规则逐条解析合并（按 path 去重，先出现的命名保留——`<npm>`+`<pnpm>` 双声明同一目录时只留一份）；坏条目跳过（path 须相对、不逃逸；精确目录须存在）。
- **采集进快照、读路径纯快照**：`snapshot` 的 `collectEntry`/`collectWorktrees` 调 `workspace.Resolve` 组合结果进 entry（`WorktreeInfo.Workspaces`，主区经 `Entry.Main`）；解析函数是纯函数，修正发生在代码或规则，不发生在缓存值。
- **写侧入口**：CLI `cube project config [query]`（TTY 交互循环：初始化固化 / 添加 / 移除 / 恢复默认，未来 cube.json 新配置节同在此扩展；原 `workspace init` 已被取代移除）；Web `GET project/workspace/get`（生效清单读快照 + declared 标记 + 规则清单——未声明时返回默认规则，编辑起点即当前生效配置）+ `POST project/workspace/save`（规则清单整节覆盖，写侧结构校验严格：坏条目整体拒绝；glob/特殊规则即使暂无命中也可保存；空清单 = 显式「无 workspace」）+ `POST project/workspace/reset`（删节恢复默认规则），编辑入口在项目详情抽屉（从项目上下文直达）。

### 3.3 opener：Opener 值对象 + settings.json + icon

`Opener` 是**值对象**（`internal/domain/opener/opener.go`：`Name/Title/Actions/Icon` 字段 + `Roles()`/`Summary()` 纯派生方法）：按 role 各配一条**动作串** `actions: map[role]<kind>:<模板>`（1038 前置改造），存储形状即领域实体，无独立接口/实现分层。`validateOpener` 承载校验与归一化（name 非空、title 补默认「用 {name} 打开」、逐 action 校验、icon 校验），读写边界共用（store 的 Normalize；读侧坏条目跳过 + 内存补 title，写侧坏数据中文错误不落盘）。role（`open-dir`/`open-file`/`diff-dir`/`diff-file`，见 `internal/domain/opener/role.go`）是纯参数约束（槽个数 1 或 2，per-role 动作局部校验，role 间无一致性约束），声明了哪些 role = actions 的键集合。动作的解析/组装/执行收敛在 **`action.go`** 包级函数：动作 kind **`exec:`** 命令（sh 风格分词 `tokenizeCmd`，含空格 token 引号包裹，未闭合引号校验期报错；`$0/$1...` 占位符可嵌在 token 内（如 `--wd=$0`），无占位符时路径追加末尾；cmd[0] 自引用替换 `resolveBin`：为 `cube` 或以 `/cube` 结尾时换成当前进程可执行文件）；**`url:`** 链接（`/` 开头为站内路由——拼 baseURL（装配注入，来自 config `server.port`，opener 包不 import config）+ 占位符 query encode 后经系统 opener（macOS `open`）打开；`http(s)://` 开头为外部 URL，占位符照常替换）。执行入口 `Service.Open(opener, role, slotArgs...)`：role 支持校验（不支持即中文错误，调用方无需再核对）→ `runAction` 组装并经 `Executor`（`internal/domain/opener/executor.go`）启动子进程——**环境（executor/baseURL）留在 Service，Opener 纯数据不带进程设施**，默认执行器走 `os/exec`，测试注入 fake。

`icon` 为 `*icons.Icon` **可空**（nil = 未配置），声明只判别渲染方式（`lucide` 图名 / `image` base64 PNG）；后端不再填默认值，**未配置时的默认 icon 兜底归前端渲染层**。icon 声明语义（`Icon` 类型 / 类型枚举 / `ValidateIcon`，nil 视为合法可选）共享在 `internal/domain/icons`（跨领域：opener / scanRules / forge 等共用；nil = 可选语义，默认值策略归各域）。icons 同时承载图标提取：`.app → icns → PNG`（1016）与任意源提取（1040 增补，`ExtractFromSource`：本地图片文件 / http(s) URL 含 favicon.ico——ICO 容器手解，统一缩放 ≤64px），出口为 `POST /api/icon/extract`（见 API 表 Icon 节）。

**intent（打开意图，`internal/domain/opener/intent.go`）**：场景枚举（开放增长），多对一映射到 role——`dir`/`terminal`/`git`/`workbench`/`ide`→open-dir，`file`/`doc`→open-file，`diff-dir`/`diff-file`→同名 role。intent 是**选择层**概念（openerIntents 节键空间与调用点选 opener 的依据），不渗进 `Service.Open(opener, role)`；`Service.DefaultOpener(intent)`/`Intents()` 承载解析。CLI `open`/`open-path`/`diff` 的 `-o` 三态：不传用该 intent 默认（未配置报错引导）、裸 `-o`（flag NoOptDefVal）交互选择、`-o <name>` 按名模糊匹配（多项 TTY 交互）。前端**快捷打开位按意图槽位**（`quickIntents`：workbench/git/terminal/dir × 目标策略）取默认 opener，未配默认的槽位隐藏、不回落其它 intent 的默认。

**url 动作的前端直开**：cube 页面内的打开入口（projects/md/workbench）对 `url:` 动作不回后端（后端会经系统 `open` 用默认浏览器、丢同源上下文）——`tryOpenUrlAction`（`web/src/lib/opener-action.ts`）按与后端同规则渲染（站内占位符 encodeURIComponent、外部照常替换）后在当前浏览器新 tab 打开；分流收敛在 `useOpenerOpen().run()` / `useProjectOpen().run()`。该路径不经过后端打开链路，目录打开（open-dir / project-open）由前端补调 `POST /api/usage/record` 补记 usage（文件打开不记——usage 口径是项目/目录打开；diff 直开不记）。

**「打开工作台页」不设独立 opener 实现**：站内路由由 `url:` 动作承载（如 `"workbench": "url: /workbench?path=$0"`，baseURL 注入见上）；历史形态（webOpener 实现、exec opener 组合 `cube ui workbench` 命令）均已退役。Web 前端应用内入口仍是路由跳转，独立于 opener 体系。

**opener 数据存 `settings.json`**：`openers` 节为纯清单（Spec 数组）；`openerIntents` 节为意图配置 `{ [intent]: {defaultOpener?, openers?} }`——`openers` 候选可选、缺省 = 声明了对应 role 的全部 opener（`Intents()` 读侧合成；落盘形状是 store 私有细节，域内统一为稠密 `[]IntentInfo`，见 6.2）。校验收敛在写边界：`SaveIntentDefault` 要求 opener 存在且声明该 intent 对应的 role（必死配置不落盘）；openers 节每次落盘经 `OnChange` 级联 `normalizeIntentInfos` 清理失效引用（默认/候选指向的 opener 不存在或 role 不符即清，清空的条目落盘省略）——`DeleteOpener`/`SaveAllOpeners` 的连带清理即由它承载；失效默认不在读侧静默过滤，`DefaultOpener` 调用时校验并报中文错误；`DeleteIntentDefault` 幂等；未知 intent 键在加载时丢弃。（与 config.json 切割——运行中可变更的用户可管理数据）。settings.json 节级 API 在外部包 `github.com/heyuuu/x/store`：`store.LoadSection[T]`（一切读失败降级为零值/默认值）、`store.SaveSection`（锁内读-改-写 + 临时文件 rename 原子写，坏 JSON 拒写；src 为 nil 时删节）、`store.LoadSectionOrDefault` / `store.DeleteSection`；其他节语义级透传（值不变、格式随统一缩进规范化）。`internal/config` 只经 `Config` 的路径方法提供 settings.json 路径。openers / forges / forgeAccounts / scanRules / cloneRules / tplSources 六个清单节的 save / delete / save-all 同构算法收敛在 `pkg/xstore` 的 `KeyedSliceStore`（泛型，keyed.go），各域保留领域校验与 load/save 通道；其复用的通用切片 / 文件系统原语来自外部包 `github.com/heyuuu/x/xstd`（`xslices` / `xos`）。**清单写接口整项化（1046）**：唯一键是各 domain 的私有实现（不出 API、不导出 Key 类型）——delete 提交完整单项、domain 内算唯一键定位（只按键匹配）；save-all 以提交清单整节覆盖（顺序即落盘序，last-write-wins 不合并；逐项走与 save 相同的校验 + 节内查重，任一失败整体不落盘；空清单清空节；读侧不可见的坏条目随覆盖丢弃；副作用与单项 delete 对齐：opener 移除连带清 intents 引用、forge 移除级联删 account、account 掩码 token 按唯一键沿用旧值、scan 规则成功后重扫）。前端 settings 页写成功后全量重拉受影响查询（服务端为唯一事实源，拖拽乐观顺序在 save-all settle 后即回落）。`opener.Service` 每次**直读不缓存**（Web 保存即生效）；条目级坏数据跳过不阻断；写侧（`SaveOpener`/`DeleteOpener`/`SaveAllOpeners`）先走领域构造校验，坏数据中文错误不落文件。迁移未做代码（用户手动 jq 迁移）。

### 3.4 App 装配

`app.New()` 返回未初始化的空壳 App（`internal/app/app.go`）；root 命令的 `PersistentPreRunE` 调 `a.Init(cfgFile, debug, local)` 完成组装：config.Load → logger.Init → `di.RegisterAll` 构建 DI 容器（`github.com/heyuuu/x/di`）——各 service / handler 的构造函数注册在 `internal/app/boot.go` 的 serviceFactories / handlerFactories 清单（带 generate 注入点标记，`just gen domain` 以此为锚点追加）。`cmd.Execute()`（`internal/cmd/root.go`）在 `cmd/cube/main.go` 里调用；命令工厂收 `*app.App`，RunE 经 `a.XxxService()` 快捷方法或 `a.Container()` 取依赖。Init 之前调用读 API 会 panic。**无全局单例、无 `app.Default()`**（「惰性」仅指 cmd 层触发时机——不进 RunE 的路径全程零装配，装配本身仍是显式一次性构造）。

**service 生命周期钩子**（`internal/app/hooks.go`，可选实现，app 层经 `di.AllOf` 类型遍历分发，未实现即跳过）：

- `OnServerStart()` / `OnServerStop()`：常驻 server 启停后台任务（`app.StartBackgroundJobs` / `StopBackgroundJobs` 分发）。project 定时刷新、usage 启动 compaction 挂在这两个钩子上；CLI 短命进程不调用。

### 3.5 配置与环境分离

**dev / prod 双环境**（见 [`docs/proposals/archived/1026-环境分离/`](../proposals/archived/1026-环境分离/)）：环境身份由 `version.IsDev()` 推导——二进制被 ldflags 注入了正式 version（`just build` / `just install`）即 prod，无注入（源码直跑、air、`just run`）即 dev。默认配置目录随之分流：dev → `~/.config/cube-dev/`，prod → `~/.config/cube/`。跨环境数据不做工具迁移：config 人工 diff 合并，usage 记录各自独立积累。

`config.json` 按 domain 分节。`--config` 指定 config.json **文件路径**（优先级最高，dataDir 缺省取其所在目录），`--debug` 开 debug（只影响 logger 初始化）。配置文件缺失降级为默认值；JSON 解析失败报错退出。**无热 reload**（配置改动重启生效；settings.json 用户数据走各域 save API 即时生效）。

### 3.6 server 进程管理（HTTP 模式）

server 的进程管理（探活、关停）走 **HTTP 应用层**，不依赖 pid 文件、信号、系统守护。设计背景见 [`docs/proposals/archived/1001-server后台常驻与HTTP管理/`](../proposals/archived/1001-server后台常驻与HTTP管理/)。

- **探活**：`serverStatus(baseURL)` GET `/api/system/status`，验证返回 `app=="cube"` 才算 cube server 在跑（防「别的服务恰好占同端口」误判）。status 同时返回 `instance`（进程启动时随机生成的实例标识，重启后变化）。探活/关停的 HTTP helper 在 `internal/cmd/server/helpers.go`（原 `internal/server/client` 包已并入）。
- **关停**：`serverStop(baseURL)` POST `/api/system/shutdown`（带 HMAC 时间戳鉴权，5s 窗口防重放）→ server 自发 SIGTERM → `internal/server` `Server.Start` 的信号监听走 graceful shutdown。和 Ctrl+C 同路径。轮询确认**发起 Stop 时的旧实例**下线——按 status 的 `instance` 判定（探不到 cube 或 instance 换人均算；launchctl 保活会在旧进程退出后立刻拉新进程占回端口，只看「端口上还有没有 cube」会误判没停掉）。返回 `replaced=true` 表示端口已被新实例接管。
- **启动形态只有前台**：`cube server start` 前台阻塞（Ctrl+C 退），不自 fork 后台（原 `-d`/`serve.Fork` 已移除，1036——写死 argv 不透传 `--config`、启动失败无声的结构性问题，且常驻由系统保活承担后已无消费者）。**不写 pid 文件**。
- **端口单一事实源**：config 的 `server.port`（dev `6001` / prod `6101`，由各环境配置目录自带）。**不再支持多端口多实例、无 `-p` flag**——md/status/stop 等依赖 server 的命令一律读 config 端口，从根上杜绝「传了自定义端口被遗忘」的孤儿实例。常驻形态：prod 走 launchd LaunchAgent（`com.heyuuu.cube`），dev 走 air。
- **不做 lazy 拉起**：依赖 server 的命令（未来的 md 等）只探测、不自动起，server 由用户显式 `cube server start` 启动（nginx 模式）。

### 3.7 git 访问层：读/写统一走原生 git

`pkg/git` 是唯一的 git 访问层（历史：v3 早期读走 go-git 库、写走系统 git，双轨；已统一为原生 git）。原因：go-git 的 Status 不加载全局忽略链（与真实 git 输出有偏差）、忽略过滤发生在全量 diff 之后导致大仓库秒级卡顿；原生 git 行为与用户日常 git 完全一致且自带 index 缓存。原「避免 CLI 批量采集 fork 开销」的动机随 snapshot 异步采集（3.2）消失。实测复核数据与源码分析见 [decisions/go-git否决.md](../decisions/go-git否决.md)（2026-11-08，含复核条件）。

- **封装边界**：包外只调用类型化函数，缺什么在包内新增封装（含输出解析，返回类型化的 struct/切片/集合）；不 exec git、不拼子命令参数、无「调用方传 args 的通用执行口」（曾有 `RunRead`，已移除）。平台/环境兼容（quotePath 转义 / locale / pager / `diff --no-index` 退出码 / 忽略目录折叠语义）单点收敛在包内。规则见 AGENTS.md 第 13 条；测试 fixture 除外。
- **写操作**（`git.go`，Clone/Push/Commit 等）：stdio 透传，用户看到 git 真实输出。
- **读操作**按主题分文件（共享执行核 `run.go` 的 runOut/isGitRepo）：`refs.go`（Refs/BuildRef/HeadRef/CurrentBranch/DefaultBranch/AheadBehindRemote/HeadSha 等 ref 查询，ref 统一为 `Ref` 值对象——Name/ShortName/Remote/Branch + 谓词）、`remote.go`（Remotes/RemoteUrl，remote 配置查询）、`status.go`（LoadRepoStatus/LoadIgnored 等状态派生，dirty 即 LoadRepoStatus().Dirty，逐文件明细即其 Files）、`tree.go`（ListFiles/ListFilesUnder/FileShasAtRef/ReadFileAtRef/ExistsAtRef）、`diff.go`（DiffFiles/DiffNoIndex/Numstat）、`log.go`（CommitsPage）、`worktree.go`（WorktreeList / WorktreeMain / FindMainRoot——WorktreeMain 探测目录是否为 linked worktree 并返回主仓库目录（1032 归并链路的探测原语）；FindMainRoot 归并到仓库主工作树根：linked worktree 返回主仓库目录、普通仓库返回仓库根本身，非 git 目录 ok=false）。只解析机器可读输出（`for-each-ref --format` / `remote -v` / `status --porcelain=v2`（含 `--ignored`）/ `rev-list --count` / `symbolic-ref` / `ls-tree -z` / `diff --name-status -z`），不解析任何随 locale 翻译的 stderr 文案。
- **输出稳定化**（`runOut` 统一注入）：`LC_ALL=C` + `GIT_PAGER=cat` 环境变量、`--no-optional-locks`（后台读不抢 index.lock）、`-c core.quotePath=false`（中文路径不转义八进制）；status 显式 `--untracked-files=normal`（覆盖用户 `status.showUntrackedFiles=no`）。
- **非仓库判定**：`isGitRepo` 用 `os.Stat(.git)` 预判——git 报错文案随 locale 变化不可解析，靠预判把「非仓库」（零值降级）与真实错误区分开。
- **错误约定**（原 gogit 包延续）：业务空值场景（非仓库/缺 remote/缺分支）返回零值 + nil；真实读取错误返回 error。snapshot 与 cmd 层依赖此约定。
- **版本基线**：`symbolic-ref` / `for-each-ref --format` 等要求 git ≥ 2.22（2019+，实际开发机 2.29 验证通过）。

### 3.8 工作台（workbench）

git 可视化工作台（取代 SourceTree 的定位），需求群 1008/1010-1015 已全部交付归档（各提案 README 有验收记录与实现更新）。**解耦 project scan**——入口是任意本机 git 目录，不要求被 cube 管理。
- **TreeSource 统一抽象**（`workbench/types.go`）：`{type: commit|ref|worktree, id}`，前后端统一用单参数序列化 `type://id`（如 `ref://main`、`worktree:///path/to/dir`），`ParseTreeSource` 校验（commit 须 40/64 位 sha、ref 短名按 check-ref-format 核心规则挡 rev 表达式）。
- **git 信息不走 snapshot**：工作台所有 git 读直接调 `pkg/git`（实时性与内容范围不同，不混用）；读路径无缓存，实时性由前端 React Query 的 staleTime 控制。
- **面板体系**（前端 `web/src/pages/workbench/`）：注册表面板仅 `git-tree` + `content` 两类（原 code/diff/auto 三面板已合并）。`content` 面板为 `current [+base]` 视图模型——URL 参数 `current`（当前查看的版本）+ 可选 `base`（对比基准），diff 方向固定 base → current，base 缺省 = 相对基准（worktree→HEAD、ref/commit→父提交）。公共组件：`SourcePanelShell` / `FileTreePane`（树列 + 视图偏好 localStorage）、`FileContentArea` / `useFileEditing`（预览 / 源码 / diff 三模式 + 确认式轻编辑；预览按扩展名富预览——md 渲染（`components/markdown-render`，与 /md 页共用管线）/ html iframe（sandbox 仅 allow-scripts）/ 图片（`/api/workbench/file/raw`），无对应格式回落源码）。布局（面板槽位/宽度/收窄）存 localStorage `cube.workbench.layout`，旧布局 id 自动迁移。
- **文件写路径**：`POST /api/workbench/file/save`（仅 worktree 源，内容未变跳过，不做任何 git 操作）；路径安全靠 `secureJoin`（显式拒绝 `..` 段 + Clean + 前缀校验）。
- **worktree / 分支写侧**（1031，`internal/domain/workbench/worktree_write.go` 主题逻辑 + service.go 薄编排）：`WorktreeAdd`（三形态：branch 空 = detached / 不存在 = `-b` 新建 / 已存在 = 检出；目标目录预检；被检出分支中文拒绝）、`WorktreeRemove`（非 force 预检未提交/未跟踪/未推送，结构化 `WorktreeRemoveDenied`；主目录恒拒；删后 prune）、`BranchDelete`（被检出硬约束恒拒）、`BranchAdd`（不检出不切 HEAD，与删除对应）。git 写调用全部走 `pkg/git`（`WorktreeAdd/WorktreeRemove/WorktreePrune/BranchDelete`）；成功后经 `cacheRefresh` 回调（装配注入 `project.Service.RefreshSnapshot` → `snapshot.RefreshOne` 定向刷新主项目快照，避免 workbench 反向依赖 project）。前端对话框在 `panels/worktree-write.tsx`（新建/删除/删分支，删除含 force 勾选与联动删分支，删当前目录导航回主副本）。
- **PTY**（`workbench/pty.go`）：`GET /api/workbench/pty` WebSocket（huma 外原生 mux），JSON 帧 input/resize（入）、output/exit（出）；每连接起 `$SHELL` 子进程（creack/pty），断开杀进程；server 停机经 `OnServerStop` 钩子回收全部会话。前端多终端 = tab + 横向分屏，偏好（字体/字号/高度）localStorage。
- **安全边界**：接口可读任意本机 git 目录 / 开本机 shell，localhost 无鉴权服务是 cube 现状，MVP 接受此边界（总纲定稿）。

### 3.9 scan/clone 规则：settings.json 分节直读（提案 1029）

scan/clone 规则数据源是 settings.json 的 `scanRules` / `cloneRules` 两个数组节（原 config.json `project` 节已移除，残留不读取；存量由用户手动迁移，同 opener 先例）。`project.Service` 对规则**直读不缓存**（`loadScanRules` / `loadCloneRules` 加载即转换校验：**path 必须绝对路径**，`~/` 前缀不再由 domain 展开——路径展开职责收敛在出口层 `cmd.ExtendPath`，domain 只认绝对路径；非绝对/坏路径降级跳过），Web 保存即生效。写侧（`SaveScanRule` / `DeleteScanRule` / `SaveAllScanRules` 及 clone 对应方法，`internal/domain/project/settings.go`）校验收敛在写边界，坏数据中文错误不落文件；scan 规则的 save/delete/save-all 成功后立即重扫项目列表（毫秒级）。scan 规则键 = `path` 原串（编辑 path 等价删旧存新），clone 规则键 = `repoHost`+`repoPrefix`。icon 声明语义共享自 `internal/domain/icons`（见 3.3）。

### 3.10 文件存储原语：github.com/heyuuu/x/store（提案 1033，后上游化）

文件存储通用原语收敛在外部包 `github.com/heyuuu/x/store`（1033 先落在本地 `util/store`，135df27 起抽到个人基础库上游化维护；只依赖标准库，路径由调用方给定，无环境副作用；按主题分文件 atomic / json / jsonl，主题间无依赖）：

- `WriteFileAtomic`（atomic）：tmp 同目录 + rename 原子写（rename 原子性只在同文件系统成立，故 tmp 必须落目标同目录），目标目录不存在自动递归创建，中途失败清理 tmp。
- `SaveJson` / `LoadJson`（json）：缩进 + 尾换行（存储文件常被人工翻看）；`LoadJson` 对文件缺失返回哨兵错误 `ErrFileMissing`，调用方据此时降级（区别于读失败/解析失败）。
- `AppendJsonl` / `WriteJsonl` / `LoadJsonl` / `IterJsonl` / `IterJsonlReverse`（jsonl）：O_APPEND 单行追加、全量原子重写（tmp+rename，compaction 类场景，重写瞬间并发 append 会丢）、全量读（坏行跳过并 slog）、正向/逆向流式逐行迭代（`iter.Seq2[行号, T]`，随时 break 停止；逆向为分块从文件尾扫描、不整读文件，行号是物理行号）。

存量消费方：snapshot `Save`（`WriteFileAtomic`）、config `Load` 与 settings `readDoc/saveDoc`（`LoadJson`/`SaveJson`）、usage JSONL（`AppendJsonl` 等）、forge 拉取缓存落盘（persist.go）。config / settings / snapshot 三处手写原子写已全部收敛至此。1034 的 usage JSONL 存储也以此为基础。

### 3.11 forge 配置：git 托管平台实例（1040）

forge 是 git 托管平台实例的 host 级配置（github.com / 自建 gitea.example.com:3000 …），限定 git 仓库的托管平台。`Forge{host, kind, icon}` 存 settings.json 的 `forges` 节（`forge.Service` 直读不缓存、写侧校验，模式同 3.9 scan/clone 规则）：

- **kind 四值枚举**（API 方言，决定 1041 account 拉取能力）：`github` / `gitea` / `gitee` / `generic`（无 API 仅展示）。
- **host 是唯一键**：归一化规则 = 去空白 + 小写 + 去尾部点号（`NormalizeHost`）；写侧校验纯域名[:端口]（拦scheme/路径/用户手误）；编辑 host = 删旧存新。
- **repo→forge 匹配在前端**：前端从 settings API 拿 forge 列表，按项目快照解析 remote host 查表展示 forge icon（projects 列表与树两模式，名称旁小图标）；1042 修：快照新增 `snapshot.remotes`（全部 remote 的 name+url，采集侧一次 `git remote -v` 同时派生 repoUrl 与 remotes），多 remote 项目（如 github+gitee 双源）按全部 host 匹配、命中几个展示几个 icon（`repoHostsOf` / forge 筛选谓词入参同步改为 host 数组）；**不把 forge 信息写进快照**，读路径零改动。
- 出口：CLI `cube forge [list]`、Web settings 页 Forge 分区（增删改 + 拖拽排序，Sheet 抽屉表单）、API `forge/list` `forge/save` `forge/delete` `forge/save-all`。

### 3.11a forge account 与远端拉取对账（1041，1044 简化）

在 forge 之上补 account 配置 + 一个出站拉取能力（数据存 settings.json 的 `forgeAccounts` 节，模式同 forges 节）。1044 起 **namespace 配置实体移除**——实测各平台「按命名空间列仓库」端点分裂且部分不可靠（github/gitee 的 `/users/{path}/repos` 只回公开库、gitee org 列表会混入无权限的幽灵条目），只保留「认证账号拉全量」这一条可信口径（详见提案 1044）：

- **Account 是纯 API 凭证**：`Account{forgeHost, username, token}`，唯一键 `forgeHost+username`。token 只用于调平台 API 拉仓库列表（含私有库与所属组织仓库），**git 操作仍走本机凭证**（token 从不参与 git 传输）。token 必填（匿名无认证端点可用）；generic forge 拒配。token 对外只以掩码形态出 API（`forge.TokenMasked`），save 提交掩码值视为「未修改」沿用旧值。
- **API 客户端沉淀在 `pkg/gitapi`**（与 `pkg/git` 成对）：统一 `Client` 接口 + github/gitea/gitee 三方言实现（`NewClient` 按 kind 分发；认证差异：github Bearer / gitea `token` header / gitee `access_token` query——query 认证在 URL 构造前注入），三方言统一走 `GET /user/repos` 认证端点分页拉全量（短页即停）；自建站点 scheme 自适应（https 失败降级 http 记忆）；401/403 统一映射 `ErrUnauthorized`；HTTP client 可注入 fake，测试不打真实外站。对外只暴露 `RemoteRepo{name, fullName, cloneUrl, defaultBranch, updatedAt}`，owner（namespace）从 `fullName` / URL path 推导，纯展示维度。
- **拉取是手动/低频触发的出站调用**（不进 snapshot 常驻采集）：`FetchAccount` 同步执行（HTTP 超时 10s），成功结果写穿内存缓存与落盘文件 `cache/forge-repos.json`（按 `host/username` 键，含 fetchedAt，原子写；重启不丢、新鲜度前端展示）。
- **对账是纯函数**：`forge.RepoKey` 把两端 URL 归一到 `小写host/小写path（去 .git）` 再比对（复用 `git.ParseRepoUrl`，ssh/https/带端口各形态同键）；`forge.Reconcile(local, remote)` 产出三分——未 clone（missing）/ 本地孤儿（orphan）/ 已 clone（synced，含快照的 dirty/ahead/behind）。**孤儿定义（1044）：与该 forge 拉取到的仓库同 namespace（URL path 首段）但不在拉取结果里的本地项目**；namespace 从 `full_name` / URL 推导，forge 页仅作展示分组维度。
- **级联**：`DeleteForge` 同时清理该 host 下的 account。
- 出口：API `forge/account/{list,save,delete,fetch}`、`forge/overview`；Web settings 页 Forge 分区下挂账号子表（token 掩码展示）。

### 3.11b forge 页（1042，1044 调整数据源）

前台以「forge 上的仓库」为入口的列表视图（路由 `/forges`，全局导航与 projects 平级；样式类项目列表页、无 tree 模式）：

- **数据源 `GET /api/forge/overview`**：后端聚合全部 account 的拉取缓存 × 本地项目快照（`forge.Overview{rows, accounts}`），复用 3.11a 对账纯函数产出 `RepoRow{forgeHost, owner, status: missing|synced|orphan, repo, local?}`；owner 从 URL 推导、纯展示分组维度。页面浏览只读缓存**不触发外呼**，拉取/刷新是显式动作。
- **freshness 展示**：account 摘要条显示每个账号的仓库数 + 「拉取于 X 前」+ 刷新按钮；未拉取（fetchedAt 零值）或超 7 天标黄提示「未拉取 / 已过期」——落盘数据不会自动更新，靠显式刷新。
- **筛选/排序**：筛选 chips 每维一行、标签标注单选/多选（`FilterRow`/`Chip` 公共组件，与 Projects 页同款），URL 记忆（`?forge=` 全部/各 forge 配置序带 icon、`?status=` 全部/未 clone/已 clone/孤儿）；排序在表头（`SortHead` 公共组件，RepoUrl 按名称、更新时间按时间，循环 asc/desc/默认）。
- **列布局（1044 后）**：RepoUrl 列合并展示（forge icon 前缀 + `namespace/name`，孤儿行取本地 remote 的 URL 推导，悬停显完整 clone 地址）+ 状态 + 本地（`~` 缩写路径，`prettyPath` 同项目页）+ 更新时间 + 操作。
- **行操作不做 clone 执行**：missing 行「复制 clone 命令」（`cube clone <cloneUrl>`，clone 规则匹配仍由 CLI 流程承担）；synced 行复制路径 + 跳工作台；orphan 行复制路径。git 操作仍走本机凭证，forge 页不重造 clone/push 流程。

### 3.12 模板引擎与模板源（`template` domain，提案 1045）

模板引擎（`internal/domain/template`，原 create domain）——引擎是机制、模板是数据（`template.yaml` 协议，1009）。1045 起 git 模板源改为「**settings 映射 + 临时拉取**」轻量形态：

- **模板源映射存 settings.json `tplSources` 节**：`[{name, repoUrl}]` 数组，name 唯一键（字母/数字开头，仅含字母/数字/-/_，最长 32），节内顺序即 create 交互选择序；repoUrl 支持 `git@host:path` / `https://host/path` / 本地绝对路径。CRUD 直读不缓存（forge 同款），Web settings 页「模板源」分区管理（默认源徽标 + 缺失提醒），CLI 无管理命令。
- **引用语法四形态**（cmd 层 `parseCliTpl` 首字符判定，`internal/cmd/tpl/create.go`；`<模板源>` 可整体省略——单参数时唯一参数即目标路径，走默认源交互选模板，目标路径恒为最后一个参数）：`@<source>/<tpl>` 命名源指定模板（npm scope 式 @ 前缀，业内对照见提案 1045 D2）/ `@<source>` 命名源交互选模板 / 裸名 = 默认源 `default`（`template.DefaultSourceName` 常量）的指定模板 / `./`·`~/`·`/` 开头 = 本地路径直读。**名字 = 发布态（永远最新），路径 = 开发态（未推送改动）**。
- **create 分阶段 API，交互在 cmd 层**：domain 不含用户交互（不 import `pkg/tui`），编排（`tui.SelectItem` 选模板 / `tui.Input` 提问变量）在 `internal/cmd/tpl/create.go` 的 RunE。domain 侧链路：`Service.CheckTarget(target)`（路径预检，cmd 层先于 clone/交互调用）→ `Service.OpenSource(ref) (*Source, error)`（本地路径直读 / 名字查注册表临时 clone + 加载模板清单）→ `Source.Names()`（交互候选）/ `Source.RootTemplateName()`（根模板名，库形态空串）/ `Source.Template(name)`（缺失报错附可用清单）/ `Source.Cleanup()`（删临时目录，本地路径形态空操作）→ `Template.CheckVars(cliVars)`（--var 拼写检查，先于逐项提问）→ `Service.Generate(tpl, target, vars) (int, error)`（渲染 + init 执行，返回文件数）。
- **根模板自动选中**：模板源两形态——**根模板**（template.yaml 在源根，整个源即唯一模板，名固定 `<root>` 即 `RootTplName` 哨兵常量，含 `<>` 不会与库模板目录名撞车）与**模板库**（`templates/` 下含 template.yaml 的子目录）。未指名模板时根模板直接选中跳过交互；**自动选中挂在源的结构声明上，不挂在模板数量上**——模板库即使当前只有一个模板也仍交互选择（库增长不应改变既有源的交互行为，脚本形态不因加模板而挂到 prompt 上）。
- **create 时临时 clone 不缓存**：名字解析 → 查注册表 → `os.MkdirTemp("cube-tpl-")` + `git.Clone(depth=1)` → 用后 RemoveAll（失败路径同样清理）。无更新/dirty/对账等本地缓存状态机——这是对 a84d338 本地管理方向的回摆（url 太长的真需求只需映射，见提案 1045 alternatives）。
- **模板文件按 git 视角遍历**（`Template.WalkFile` 优先 `git.ListFilesUnder`：tracked + 未跟踪未忽略，`.gitignore` 忽略链整条生效；目录不在 git 仓库内时降级普通遍历）——本地开发态与 clone 发布态的内容口径一致，`node_modules`/构建产物等不进生成结果。
- **默认源不做自动初始化**：default 源缺失时报错指引设置页（不附建议地址）；无首次自动 clone、无安装时 seed。

## 四、命令列表

入口 `internal/cmd/root.go`，根命令 `cube`（main 在 `cmd/cube/main.go`）。全局 flag `--config`（config.json 文件路径）/ `--debug` / `--local` 走 cobra PersistentFlags 真解析（`StringVar` 闭包注入）；装配链（config→logger→app DI 容器）由 root 的 `PersistentPreRunE` 直调 `a.Init(...)` 惰性完成——不进 RunE 的路径（`--help`/未知命令）零装配。命令工厂收 `*app.App`，RunE 经 `a.XxxService()` / `a.Container()` 取依赖。错误输出：cobra `Error:` 行（终端）+ `slog`（日志）；输入类错误（flag/参数）附 usage，运行期错误（Init/RunE）不附。

**shell 集成（zsh）**：`just install` 把 `cube completion zsh`（cobra 生成，compdef `_cube cube`）与 `scripts/zsh-append.sh` 依次写入 `~/.config/cube/zsh.sh`（覆盖写，幂等），`~/.zshrc` source 该文件。append 段定义 shell 函数 `p`（= `cube "$@" --local`）与 `pz`（= `cube path` 后 cd；cd 语义决定其必须是 shell 函数而非 symlink），并用 compdef 给两者挂 TAB 补全——不手写候选，转发 cobra 补全能力：`_cube_p` 把 `words[0]` 改写回 `cube` 后直接复用生成的 `_cube`（`--local` 不影响候选，无需注入）；`_cube_pz` 调 `cube __complete path ...` 协议并抑制文件名补全回落（query 是模糊检索词，文件候选是噪音）。cmd 包当前无任何 ValidArgsFunction/ValidArgs，全部候选为子命令/flag 静态结构。

## 六、数据模型

### 6.1 Project 域（`internal/domain/project/`）

- **`Project{path, group, name, tags}`** — path 是绝对路径主键，name = `group:subpath`。git 状态不入实体，由 `Service.Snapshot(path)` 查项目快照补出。
- **`ScanRule{Group, Path, MaxDepth, Icon, Tags}`** — 扫描规则（Icon / Tags 可选；Tags 命中该规则的项目统一追加的标签，如 个人/公司/开源，与探测 tag 合并且清洗去重）。存 settings.json `scanRules` 节，加载即转换校验（path 须绝对路径、坏路径降级跳过），详见 3.9。
- **`CloneRule{RepoHost, RepoPrefix, LocalPath}`** — clone 路由规则，按 host + path 前缀匹配，多条取 prefix 最长者。存 settings.json `cloneRules` 节，键 = host+prefix。
- **`snapshot.Entry{Remotes, DefaultBranch, Branches, Main, Worktrees, UpdatedAt}`** — 项目状态快照（包历史 gitcache → projcache → snapshot）；`Remotes` 为全部 remote 的 name+url（1042，前端 forge icon 匹配用，origin 地址经 `OriginURL()` 派生）；`DefaultBranch` 从本地分支清单推断（master/main 优先）；`Branches` 为本地分支列表（`LocalBranchInfo{Name, ShortName, Upstream, Ahead, Behind}`，v5 起随 `git.Refs` 单进程顺带采集 upstream 跟踪状态）；`Main` 为主工作树（`WorktreeInfo` 值字段，恒存在）；`Worktrees` 为 linked worktree 列表（主目录不含在内）；`WorktreeInfo{Path, Branch, Detached, Dirty, Workspaces}`（`Workspaces` 为该根的 workspace 成员，`workspace.Workspace{Name, Path}`，Path 相对所属根）；`UpdatedAt` 为本次采集时间。cacheVersion = 5。

### 6.2 Opener 域（`internal/domain/opener/`）

- **`Opener` 值对象**（`Name/Title/Actions/Icon` 字段 + `Roles()`/`Summary()` 派生）：存储形状即领域实体——按 role 各配一条动作串（详见 3.3）；`validateOpener` 校验与归一化（title 补默认），读写边界共用。
- **`action.go` 包级函数** — 动作的解析（`validateAction`/`parseAction`/`tokenizeCmd`）、组装（`buildActionArgs`）与执行（`runAction`，经 `Executor`）；环境（executor/baseURL）在 `Service`，实体纯数据。
- **`Role` 枚举**（`role.go`）：`open-dir`/`open-file`（1 槽）、`diff-dir`/`diff-file`（2 槽）——槽约束 + 能力声明，per-role 动作局部校验、无跨 role 一致性约束。
- **`Intent` 枚举 + `IntentInfo`**（`intent.go`）：intent（9 值，多对一映射 role）；`IntentInfo{Intent, DefaultOpener, Openers}` 为意图状态的统一内存形状（稠密、`intentOrder` 固定序，store 内存形态与 `Intents()` 输出共用）。`openerIntents` 节的落盘形状是 store 私有细节（`settings.go` 的 `newIntentInfosStore` 内本地 Spec 经 `store.WrapperStore` 互转，空条目落盘时整条省略），不对外暴露。
- **`Icon{type: lucide|image, value}`** — 图标声明（`internal/domain/icons` 共享类型；opener 侧 `*Icon` 可空，nil = 未配置，默认 icon 兜底归前端）。

### 6.3 Usage 域（`internal/domain/usage/`，JSONL 文件存储）

统一的项目使用记录：一次「使用」= 一次 opener 打开事件，所有打开入口（Web `project/open`、CLI `cube open`、alfred `project-open`）在打开成功后追加一条。`open_path` 与 Web `opener/open`（打开任意路径）**不记**——语义是「打开路径」而非「使用项目」，目标可能不是项目，脏 key 永不过期会污染排序信号。

**记录**（`Record`，JSONL 行，文件 `dataDir/state/usage.jsonl`、**不放 `cache/`**——它参与排序语义）：

```json
{"time":"2026-08-27T21:03:14+08:00","project":"/Users/heyu/Code/heyuuu/cube","opener":"idea","dir":"/Users/heyu/Code/heyuuu/cube--web/server"}
```

- `time`：RFC3339，行序与它单调一致，承担排序职责（追加不变量：行序 = 时间序）；
- `project`：主项目**绝对路径**（project 的唯一标识，排序 join 用它；worktree / monorepo 子目录打开时也恒记主项目路径，归并键不分裂）；
- `opener`：opener 名；
- `dir`：实际打开的目标目录绝对路径（主项目根打开时省略；worktree 为其绝对路径，1032 已在全部打开入口写入；workspace 为其绝对路径，1030 已生效）。字段演进约束：只增不改（新字段加 `omitempty`），读取方容忍缺失字段（无 schema 前后向兼容）。

**读写原语走 `github.com/heyuuu/x/store`**（1033）：追加 `O_APPEND` 单行（POSIX 小块 append 原子，CLI 短进程与常驻 server 并发追加安全，全程无 flock）；读侧全量读 + 内存去重（同 key 留更新行）：

- `LatestByProject() map[path]time`：最近使用信号源（`lastUsedAt` 展示与各出口排序）；
- `LatestOpeners(project, limit)`：alfred 的 opener 排序偏好（同项目常用 opener 靠前）；
- `RecentPaths(limit)`：按 path 去重取最新、最近使用倒序（workbench 入口的「最近打开」清单，任意 git 目录都算，含未收录项目）。

**触发补记**（Web 出口，`handlers/usage_handler.go`）：`POST /api/usage/record`（body: project 绝对路径 + 可选 opener/dir）给「不经过后端打开链路」的使用场景补信号——workbench 进入成功（opener 留空，只贡献项目最近使用、不进 opener 偏好统计）与 url 型 opener 动作前端直开（见 3.3）。写侧只校验 project 为绝对路径，workbench 入口的「最近打开」读侧走 `GET /api/usage/recent-paths?limit=`（缺省 5）。

**排序的分工**：排序与筛选同侧——Web 在前端做（`project/list` 返回原始扫描序 + `lastUsedAt`，页面提供「最近使用 / 默认 / 名称」排序单选，默认最近使用）；alfred `project-search` 自带私有 `sortByRecentUsage`（最近 10 条按使用时间倒序置顶、其余原序；以 map 传参，不依赖 usage 包）；CLI `list` 按扫描序输出，不排序。

**清理**：server 启动时 `OnServerStart` 钩子异步 compaction 一次——tmp+rename 整体重写，每个 `(project, opener, dir)` 组合留最新一条 + 30 天内记录（重写瞬间并发 append 的极少数记录会丢，usage 是 best-effort 信号，接受）。保留期常量 `retentionDays = 30`（不进配置文件）。历史 sqlite 数据**未迁移**（旧表只有 alfred 记录，价值低，新文件从空开始）。

> gorm + sqlite 依赖已随本域落盘方案移除（`db` 包、`data.db`、AutoMigrate 接线均已删除）。

### 6.4 Workbench 域（`internal/domain/workbench/`）

**无持久化实体**（不入 sqlite/config），纯运行期编排：类型定义（`TreeSource` / `WorktreeStatus` / `DiffEntry` / `FileResult` 等）+ Service 方法（Info/Refs/Commits/WorktreeStatuses/Tree/ReadFile/SaveFile/DiffTrees/ReadFileDiff/Changes/ServePty）。文件布局遵循 Service 包布局规则：`service.go`（Service struct + 全部方法）/ `types.go` / `file.go` / `diff.go` / `pty.go` / `helpers.go`。

### 6.5 Forge 域（`internal/domain/forge/`，1040）

- **`Forge{Host, Kind, Icon}`** — git 托管平台实例配置（host 级），存 settings.json `forges` 节，host 归一化后是唯一键。Kind 四值（github/gitea/gitee/generic）决定 1041 account 拉取的 API 方言。
- **`Account{ForgeHost, Username, Token}`** — forge 上的纯 API 凭证（1041），存 `forgeAccounts` 节，键 = forgeHost+username；token 只调平台 API，git 操作走本机凭证，对外打码。1044 起是 forge 下唯一的关联配置。
- **`pkg/gitapi`** — git 托管平台 REST API 客户端（1041，与 `pkg/git` 成对）：`Client` 接口 + github/gitea/gitee 三实现，统一 `ListAccountRepos`（三平台 `/user/repos`）出 `RemoteRepo`；token 认证、分页拉全量、scheme 自适应都在包内。1044 起不做按命名空间列仓库（端点不可靠）。
- **`cache/forge-repos.json`** — account 拉取结果落盘（1042，键 = host/username，含 fetchedAt，纯缓存语义可整体删除），内存为一级缓存写穿。
- 纯函数：`RepoHost`（repo remote URL → host，复用 `pkg/git.ParseRepoUrl`）/ `MatchHost` / `NormalizeHost` / `ValidateHost`；`Service` 提供直读与写侧校验（`Forges` / `SaveForge` / `DeleteForge`）。详见 3.11。

## 九、已知 gotcha

- go 源码与 go.mod 都在**仓库根**（`cmd/` `internal/` `pkg/` 分目录），module path 是 `cube`；`go build` / `go test` / `just` 各命令都在仓库根跑。
- **`web/dist` 不入库但 go:embed 需要它存在**（`web/embed.go` 直接嵌入 `web/dist`）：clone 后首次构建前必须先 `just build-ui`。改前端改 `web/`，不要手改 `web/dist/`。
- `.gitignore`：仓库根的 `tmp/`（构建产物）、`runtime/`（历史测试产物，testfixture 已改用系统临时目录）、`.zcode/plans` 等 plans 目录；`web/.gitignore` 的 `dist/`、`openapi.json`（本地生成）、`node_modules`。
- 默认配置目录按环境分流：dev `~/.config/cube-dev/`、prod `~/.config/cube/`（非项目目录），运行期状态（`state/usage.jsonl`、`cache/snapshot.json`、`log/app.log`）都落在对应配置目录。改 launchd plist 后必须 `bootout` + `bootstrap` 才会重读（`kickstart -k` 只重启进程）。
