# RFC 收尾

把一个开发完成的 RFC 置为 `done`。机制全文见 `docs/rfcs/README.md`；两者冲突时以 README 为准。

## 步骤

1. **定位 RFC**：按编号或名字匹配 `docs/rfcs/` 目录，读 RFC.md 全文。
2. **确认状态**：应为 `developing`。若仍是 `accepted`，说明开发期间没维护状态——先与用户确认实现确实完成，把状态过到 `developing` 再收尾；若根本没开发，不走本技能（回去 rfc-continue）。
3. **逐条核对验收标准**（需求描述里的 `- [ ]` 清单）：对照实际代码逐条确认，真正达成的才改成 `- [x]`。未达成的不许硬勾——要么继续开发（rfc-continue），要么与用户确认后移入遗留问题。
4. **填「实现记录」**：与最终方案的偏差、开发中的关键决定、涉及的文件路径（如 `pkg/vfs/fs.go`）。没有偏差也至少列出涉及文件——这是日后回顾"当时怎么做的"的唯一线索。
5. **填「遗留问题」**：done 时仍未解决的事项；衍生出新需求的，用 rfc-create 开新 RFC 并在此写链接（如"见 rfc-011"）。没有则写明"无"。
6. **更新 front-matter**：`status: done`，`updated: 今天`。
7. **收尾建议**（按用户意愿执行）：
   - 跑 rfc-validate 自查一遍；
   - 提交信息：`docs(rfcs): 完成 {编号}-{需求名}`。

## 红线

- 验收标准未全部真实达成，不得置 `done`。
- 收尾只改文档；代码提交与分支操作按用户指示进行。
